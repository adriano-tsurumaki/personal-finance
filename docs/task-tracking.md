# Documentation maintenance

Keep repository documentation self-contained. Document implemented behavior,
architectural conventions, financial rules, release notes, and validation evidence
alongside the code they describe.

Before updating a claim, inspect the relevant implementation and acceptance
criteria. Record verification dates and evidence where useful, distinguishing
source inspection, existing test coverage, newly executed tests, and manual checks.

Describe known limitations in the relevant specification and release notes when
they affect supported behavior. Distinguish those limitations from delivered scope.
Update documentation when behavior changes, and preserve relevant historical
validation results without presenting them as newly executed checks.
